# Changelog (threedog)

What changed in each version and how a game upgrades.

## Unreleased

- Fixed: on WebGPU the engine now asks the device for the adapter's own `maxBufferSize`, `maxStorageBufferBindingSize`, `maxSampledTexturesPerShaderStage` and `maxSamplersPerShaderStage` (as it already did for the color attachment limits) instead of WebGPU's defaults. Before, `voxelGI` on a scene of about a million triangles or more failed every frame with `Buffer size exceeds the max buffer size limit` (its triangle buffer passed the default 256 MB), and a material with more than 16 textures counting the lights' shadow maps failed with only `Invalid PipelineLayout`. Measured on one desktop GPU: buffer 256 MB to 2 GB, storage binding 128 MB to 2 GB, textures per stage 16 to 48; samplers stay where the adapter's own limit is 16. A game's own renderer keeps the limits the game gave it.
- Docs: recipe 63 section 7 says `world()` stays in a scene with no content (the player is a record in it); recipe 56 "Mistakes" says computed vertex colors are linear.

## 1.2.0 (2026-11-10)

- Fixed: shadows on tier 'low' no longer smear. With `engine.shadows.cascades(...)` the single low-tier map now covers `maxFar / count` (shifted toward the view), so its texels are as fine as one cascade's; a game's `count: 1` still covers all of `maxFar`. The engine sun's PCF radius follows its map size (2 on the low-tier 1024 map). A radius or map size the game set (any value other than the engine's default) is kept across tier changes. Trade-off: on tier 'low' far shadows end sooner (recipe 45).
- Fixed: the picture check no longer calls a light useless when it only lights `lit: true` particles; it recolors them before each capture and puts their colors back after.

- Fixed: in first person (and a follow camera's close-up), a shadow-casting point or spot light the player carries (a head lamp, a torch, within one body width of the body) is no longer shadowed by the player's hidden body, on both renderers; before, its pool had a hard black wedge on one side. The sun and other lights still cast the body's shadow; a body that is seen shadows every light as before. A point / spot light added after the camera started now gets the body's shadow too. Nothing to call (recipe 34).
- Changed: `settings.define(key, def, apply)` (on `engine.settings`) now draws its row in the settings menu: a switch for true/false, a slider for a number with `{ min, max, step? }` (a `limits` number row has 0..1), buttons for `{ options }`, labelled by `label` (an i18n key or text, else the key), in the tab `menu` names (default a new `options` tab, shown only while it has a row). Before, a defined row was drawn by no tab unless the game's own tab drew it, so it silently never showed. Upgrade: a row your own `addSection` tab draws needs `menu: false` (the menu warns once when it sees a row drawn twice); a row the menu cannot draw (a number without `min`/`max`, a string without `options`) or a `menu` naming a missing tab warns once. Unknown `define` options now throw in dev.
- New: `lightShaft(engine, opts)` in `threedog/tsl`, a cheap beam of light you can see in the air (daylight through a ceiling hole or window, a stage or lighthouse beam). A plain additive `THREE.Mesh`: sides soften by view angle, it fades where it meets geometry and near the camera, scene fog dims it, optional drifting `dust` (skipped on tier 'low'); can follow a SpotLight or DirectionalLight. WebGPURenderer only (both backends), `WebGLRenderer` throws `tsl-misuse`. Recipe 34 "Light you can see in the air" now says when to use it and when `sunShafts` / `lightVolumes`.
- New: `engine.audio.reverb({ sends, decay, size, wet, fade })`, one reverb send/return any bus can feed (generated impulse, no file), off until called, `null` turns it off; an ambience rule `{ reverb: 0.7, when: { zone: 'cave' } }` sets its wet by place (recipes/31 §9). `audio.info.reverb` shows it.
- New: particle effects take `lit: true`: the scene's point, spot, directional, ambient and hemisphere lights tint each particle's color (dust a lamp lights), the same on WebGL and WebGPU; default unchanged (recipes/64 "Lit particles").
- Fixed: `check` hints for a hand-made inventory and a hand-made reach check now read what the code does, not one spelling: each needs two signals of the job. A bag kept as a state field (`{ bag: [] }`, `S.bag.push(...)`, `.reduce`) is flagged when, within 3 lines, something is compared with a named capacity-like limit (`> RULES.capacity`, `>= this.maxSlots`; a number literal does not count); a distance against a named range (`Math.hypot(...) < RULES.reach`) is flagged beside a `hud.hint` or the E key. Tetris piece bags, ammo counts, a physics weight and a combat range beside an attack / use press stay quiet. Before, only `const bag = []` and a number threshold beside the E key were flagged.
- A `session:start` listener added right after `await engine.start()`, when the playthrough already began inside start() (`?play`, or newGame during start), now warns `session-start-missed` with the fix (listen before start, or read `engine.session.playing`); event semantics are unchanged, nothing is replayed.
- Docs: first-person start (recipe 63 §7) and which way `yaw` points (recipe 21 §3); a light the player carries, with a shadow (recipe 34); end screens are flow states (recipe 26 intro); ambience is "sounds by place" (recipe 31 §3); a `settings.define` row is drawn by your own tab, labelled by the text or `e.t(key)` you pass; `onRender`'s `dt` is the frame's seconds, the same as `onFrame`'s.

- Fixed: a post effect order that breaks scene depth only once a held effect turns on (outline after `ao` while a low preset holds `ao` off) is refused at `engine.post.add`; before, it was accepted and threw later inside the settings switch that turned `ao` on, half-applied.
- Fixed: on WebGL, `engine.shadows.cascades(light)` while another DirectionalLight (the engine sun included) casts a shadow throws `shadow-cascades` naming that light; before, every patched material failed to compile (`CSM_cascades` index out of range).
- Post effect params refuse NaN and Infinity (`post-effect`), at `engine.post.add` and at `handle.set`; finite values, negative and huge included, are kept as given.
- An atomic op's rollback is synchronous: an atomic save part whose `load()` returns a Promise is refused there (`engine-misuse`, reported; the other parts still go back) instead of being waited for, which let a failed nested op's pending load overwrite the outer op's commit. `engine.applyState` now waits for every module `applyState` hook to settle before a failure ends the request, so a slower sibling cannot write over the next request.
- Fixed: a settings switch (bloom, ao, a game row with `limits`) turned back on, or the settings module unloaded, gives back every effect it switched off, also one that left the row meanwhile (an old effect named `bloom` once a `glow` declares `about.acts: 'glow'`); before, that effect stayed off.
- `runContract` (`@threedog/tools/contract`) now returns a Promise: write `await runContract(...)`. Its small engine uses the real `saves.define` and install check, so a module the engine would refuse (a save key defined twice, an unknown field or a bad `first`, an `install` that returns a Promise) fails the contract instead of passing it, and the save round trip loads parts by `first` and waits for a part load that returns a Promise, as `saves.load` does.
- Rule R67 no longer checks `saves.register` calls: that name was removed.
- Fixed: on WebGPU a renderer borrow (a pass, an `onRender` hook) that turned off `scene.fogNode` and threw left the fog off for good; `scene.fogNode` is put back like `scene.backgroundNode`.
- Fixed: with WebGL cascaded shadows the path-traced photo and the gallery's `game` light saw one sun per cascade (3 cascades at intensity 2 lit like 6); they now see the one sun. The engine marks such parts (core/scene/drawOnly.js; a clone is not marked) and every scene copy leaves them out.
- Fixed: a path-traced photo of far plants drawn as impostor cards traced one small card per species near the origin; the cards are now left out, and `pathTraced.untraced` says the far plants are not in the traced photo.
- Fixed: rain and snow rebuilt on a tier change on WebGPU took the old system's internal "no texture" stand-in (freed with the old material) for the game's texture; only textures the game gave are carried over.
- API cleanup (one entry per job). Internal now, not public names (they still run inside the engine; a game that called one uses the form named): `stacks.mod` (use `engine.mod`, or `ctx.mod` in a module), `ground.height`, `ground.slope`, `ground.type` and `ground.waterLevel` (a ground provider still implements them; a game samples with `engine.surface / slope / groundType / waterLevel`, `engine.ground` keeps `has` and `voidY`), `engine.commits` (a module reaches it as `ctx.commits`, a game uses `engine.nextFixed`), `assets.forget` and `rays.forget` (`engine.remove` calls both), `debug.dispose`. `engine.stacks` keeps `define`, `get`, `changed` and `describe`. What a ground provider supplies is the public type `GroundProvider` (documented in `api/ground.md`); `setGround`, `ctx.ground.provide` and `compositeGround` take it (the same members as before; `compositeGround.parts` names it).
- Renamed: `engine.freeze(owner, { ambient: true })` -> `{ still: true }`, matching `engine.still`. `ambient` is now an unknown option and throws like any other unknown key.
- Removed the old names kept as aliases (a rename removes the old name in the same change, design.md 2.6; nobody wrote them): `saves.register`, `characters.createPlayer`, `input.action`, `hud.counter`, `freeze({ ambient })` (and the same on `ctx`), and the `api-renamed` warning code they used.
- No longer `@experimental` (they are named in the recipes and sit beside stable siblings): `engine.mod`, `engine.stateApplied`, `post.get`, `post.list`, `quests.isDone`, `quests.isFailed`, `vars.setFlag`, `input.released`, `input.keysOf`, `vegetation.isRemoved`, `vegetation.restoreInstance`, `ui.isOpen`, `settings.isOpen`, `random.int`. `saves.removeAttachment` stays `@experimental` because `saves.putAttachment`, the other half of the pair, is.
- The API lock (`docs/api-surface.txt`) now has an `events` group (every event name in `events.generated.js`, so a rename or removal needs a changelog line), lists `engine.debug` member by member (`debug.view`, `debug.defineView`, `debug.override`, `debug.clear`, `debug.viewModes`...; the type of `engine.debug` is the named `DebugApi`), and skips members tagged `@internal` in the hand-written declarations too. `api/*.md` no longer lists `@deprecated` aliases or `@internal` members.
- Verb rule R69 now also covers the ways to give back: `remove` is the verb, and `clear`, `forget`, `release`, `unload` and `dispose` are allowed only where they do what remove cannot (each exception states why in the rule and in CONVENTIONS.md). `triggers.clear` stays (it empties the whole set in one call); nothing else was renamed.
- explain grows a key, `{ asset: name }` (engine.explain): it says who holds an asset (lease labels such as `content:oak`, `pickups`, `model copy`) and why a pinned or retired build is still in memory. Nothing to change in a game.
- One state-application path. `saves.load(slot, { turn })`, `session.newGame({ turn })` and `session.quit({ turn })` take the turn a save part's `load()`, an `afterLoad` or a module's `applyState(e, params, turn)` was given, and then run inside that request, as `level.load({ turn })` does; without it they wait in line as before. `engine.applyState` is one request in the state line: a second call starts when the first ended. A part registered after its save was loaded loads like a load (ops return `'loading'` meanwhile, its `afterLoad` hooks run after it); an atomic op's rollback goes past a part that throws, waits for an async part and keeps unchanged world models; `afterLoad` skips failed, blocked and disabled modules and waits for one still initializing; a `session.track` handle whose `remove()` throws no longer stops a new game or load.
- Renamed: `engine.saves.register` -> `engine.saves.define`, `ctx.saves.register` -> `ctx.saves.define`; `characters.createPlayer` -> `characters.addPlayer`; `input.action` -> `input.define` (and `ctx.input`); `hud.counter` -> `hud.addCounter`, which also returns a handle `{ set(value), remove() }`. Every other named registry already says `define` (`ops.define`, `ui.define`, `stacks.define`); one verb set: `define`, `add`, `set`, `remove`, `describe` (AI.md, rule R69).
- Picture menu: `engine.catalog('picture')` (and `threedog catalog picture`) lists every picture capability, one row each: on now, runs here or why not, cost class, one way on, recipe, main limit; `catalog(id, { offered })` adds effects not in the chain yet (no change for existing calls). Lookup names: `module:<id>`, `op:<name>`, `capability:<id>` pick the kind; a bare name tries the capabilities (`picture`, `post`, `shadows`) first, so a game module named `picture` (the game template has one) is now `catalog('module:picture')`. Combination checks (kind `mistake`: baked light plus the fill it saw; kind `note`, facts without a must-fix: metal with no environment map, bloom before a low exposure, fog color far from a flat background, the nearest caster outside every shadow box) print in `describe().render` (`checks`) and first in `threedog shot`'s hints; `describe().render.probes[].doubled` and `.lightmap.doubled` are gone, read `describe().render.checks` (id `lit-twice`). Every `@threedog/post-effects` effect carries `about` (also on its factory).
- `engine.catalog(id)` and `threedog catalog` take one prefix scheme, `module:`, `op:`, `capability:`; a bare name that is both a capability and a module gives the capability: the game template's `picture` module is now `catalog('module:picture')` (`catalog('picture')` is the picture menu).
- Perf pass 2: `engine.inspect.perf().textureMB` (and `threedog perf`'s texture MB) reads three's `texturesSize` on WebGPU and adds shadow maps to the WebGL estimate (it read 0 with TSL or procedural materials); occlusion culling no longer drops hidden casters' shadows for a second after cascades are rebuilt, and skips the test box of a batch the camera stands in; the kept shadow map refills at most once every 8 shadow frames for instance writes (streaming batches); hlod `remove()` hands its meshes back to batching.
- Far trees as cards: `vegetation.define(name, { impostor: true })` (or `{ views, size }`) bakes views of the species' own model and materials and draws everything beyond `lodRing` as one card mesh per species, lit live through baked normals; no shadow there. Off by default, instead of `lodGeometry`. WebGPU only (WebGL draws the mesh and warns). `threedog perf --only=pages --renderer=webgpu --impostor` compares.
- Module timing (`engine.profile()`, the budget's `modules` limits, the spiky marker) counts fixed hooks one step per frame, the dearest: slow frames' catch-up steps no longer read as a physics spike. hlod no longer lets batching take a mesh it took; the kept shadow map (`engine.shadows.cache`) redraws when a kept instanced mesh is hidden, swapped, stops casting or leaves the scene (vegetation rings). `threedog perf` prints each page's worst modules as median/p95.
- Adaptive quality: under load the adaptive controller now walks `engine.adaptive.steps` (default: each post effect's declared `cheaper` params, then the resolution, then effects that declare `skipOnLowTier` held off) and raises them back in reverse; a game's own knob is a `{ name, down, up }` step, `['resolution']` keeps the old behavior. The perf notice's clause is now `lowered automatically: resolution 1.5 -> 1.2, reflections cheaper (...)`, and the first dev warning reads the same. A direct `renderer.setPixelRatio` now takes only the resolution step out, not the whole controller. Recipe 15 section 4b.
- Path-traced photos: `photo({ pathTracer: () => import('three-gpu-pathtracer/webgpu') })` and `photo.trace({ samples, seconds })` (a Promise of the shot, with `pathTraced` naming what the tracer did not draw as the game does; progress in `photo.tracing`), op `photo.trace`; `take()` is unchanged. `threedog shot --path-trace [--samples n]` writes that view as a reference picture. The tracer is the game's optional package (recipe 26).
- WebGPU picture, all optional: `autoExposure()` from `@threedog/post-effects/tsl` (exposure that adapts like an eye, measured on the GPU, before tone mapping); `pcss()` from `threedog/tsl`, a shadow filter for `light.shadow.filterNode` whose edge softens with distance (it reaches the engine's cascades); a `RectAreaLight` in the scene no longer needs `RectAreaLightNode.setLTC` / `RectAreaLightUniformsLib.init` from the game, on either renderer (recipe 34). Nothing changes for a game that uses none of them.
- Reflections on WebGPU: `reflections()` from `@threedog/post-effects/tsl` (three's `SSRNode`, mirror mode, in proportion to metalness; held on low tier; recipe 34). Post effects can ask `needsBuffers: ['metalRough']`, one 8-bit target merged into the same scene render.
- Streamed content whose material the renderer has not drawn yet attaches once its shaders are compiled and its textures uploaded (a task later); `budget: { gpuMemoryMB }` on WebGPU (three's own estimate).
- Vegetation draws fewer calls for the same picture: each chunk's plants are now frustum culled by three against every camera, so the main view skips the nearest chunks behind it and each shadow camera (every cascade) draws only the chunks inside its own box. Before, the nearest ring drew in full behind the camera and every cascade drew every casting chunk. World example: 213 -> 190 draw calls (vegetation 93 -> 57), with 3 cascades 329 -> 297 (vegetation 137 -> 75); screenshots differ no more than two runs of the same build. Chunks off the main view are no longer hidden as a whole, so trees just outside the picture keep the shadows they cast into it; a felled plant is drawn at zero scale where it stood (an all-zero matrix made the chunk's bounding sphere NaN, so rays missed every plant of that chunk). Nothing to change in a game
- The engine's random pattern changes once: grain, paper, stroke and dab detail, cloud shadows, sky clouds, stars, outline wobble and film grain now use one integer hash, so WebGL and WebGPU draw the same pattern (the old sin-based hash gave each GPU and backend its own). Density, size, softness and brightness are unchanged; only the arrangement moves. The public functions keep their names and meaning: `threedogHash(vec2)` (TSL `fx.hash`), `threedogNoise(vec2)` and the post snippets' `fxHash(vec2)` take any position, as before.
- `threedog assets check` checks `needs` on the file the engine loads (the winning entry after all packs, `optimized` included, at `public/<url>`), whatever folder is checked; `content check` warns when `collide.layer` is on a tilted prop (the same rule as the runtime warning); the MCP tools `scenario` and `verify` take `freezeReload` like the CLI's `--freeze-reload`.
- Model contract: a manifest model entry can declare `needs: { nodes: [...], clips: [...] }`. `threedog assets check` errors for each node or clip the glb lost (with the closest name it has), and the load warns the same line once (`[asset-needs]`). Optional; games without `needs` are unchanged. The optimized pack from `assets optimize` now replaces only the file (url, lods, node, and a generator or Texture it stands in for), so `needs` and `prepare` survive and a generator no longer shadows the optimized file. The `optimized` pack that `threedog assets optimize` writes now swaps only the file (url, lods, a part's node): the original entry's other options (`needs`, `prepare`, `params`) stay, where before the whole entry was replaced and they were lost.
- `threedog play`, `status`, `verify` and `scenario` now check their options with the shared strict parser: a mistyped one (`play --stopp`, `verify --freeze-relod x`) fails with the list of valid options instead of running the command the default way, and `verify` / `scenario` take one scenario name. The real options (`--stop`, `--freeze-reload`) are unchanged.
- A model given to `vegetation.define({ model })` now draws with the material the game made, plus only the engine's wind / season / clouds. The copy vegetation makes of each material used to keep only what three's `clone()` knows, so a NodeMaterial's own `setupLightingModel` (the `celLighting` route), a field its class never declares and a classic material's own `onBeforeCompile` were dropped and the trees drew with three's plain lighting. Every engine copy of a material (vegetation, tinted characters and pickups, terrain textures, batching) now carries them. A code-built model named in `define` (`model: 'bush'`, a manifest generator that returns an Object3D) goes through the game's `engine.assets.onModel` first, like a content prop of that name. An attribute on only some meshes of the model (uv on the leaves only) is still dropped from the species, now with a `vegetation-ignored` notice in `describe().warnings`.
- `temporalAA` works with the vegetation module on WebGPU. Grass with wind and the near-only fade read each instance's matrix again in every patch (4 vertex inputs each), and temporalAA's velocity buffer added 4 more, past the device's 16, so its pipeline failed and a game had to fall back to MSAA. `objectOrigin()` / `instanceOffset()` (threedog/tsl) now share one input per matrix column in a program: such grass needs 9 inputs, 13 with temporalAA. The picture is the same.
- A WebGPU program that needs more vertex inputs (or buffers) than the device has stops at its build with a `[vertex-inputs]` error counting what stacked up (geometry attributes, instance matrix and color, last frame's matrix for the velocity buffer, engine patches, the material's own attribute nodes) and what to do, instead of three's raw pipeline or attribute-location error. three draws its plain stand-in for that mesh.
- Collider layers: `collision.addBox`, `collision.addCircle`, `collision.addSegment` and `collision.addObject` take `layer: 'gate'`, and a character (`createPlayer`, `npcs.add`) takes `passes: ['gate']`. Such a body walks through those colliders and every other body is stopped; `findPath`, `characters.findPathAsync`, `walkTo`, NPC paths, the navmesh and the `rapier` mover follow it. `collision.walkable` takes `passes` too, `collision.walkableAt` and `collision.resolve` an extra `passes` argument. Nothing changes for a game that uses neither (recipe 12, "Gates some characters pass").
- `engine.assets.onModel((model, name) => ...)` runs the game's setup once on every model copy the engine hands out, before it is drawn (it leaves the root's place, turn and size to the placer: dev throws on a change): `assets.model` / `modelNow` / `lod`, content props and templates, pickups, character bodies and a level file. A game that recolored engine-made props with a scene sweep can drop the sweep. Games without it are unchanged.
- A manifest model can name one node of a multi-part file: `{ url: '/models/kit.glb', node: 'Wall.001' }`. The part sits at the origin with the turn and size it has in the file, the file loads once for all its parts, and a missing node name fails naming the close names (three's renames `Wall001`, `Fence_1` are accepted).
- `threedog assets optimize` follows manifest entries `{ url, node }`: the file is optimized once, the entry is re-pointed at the optimized copy with the same node, and a node the file lacks (before or after) is reported as `model-needs`, together with the entry's `needs` checked on the optimized file.
- Collider layers reach content and levels: `collide: { layer: 'gate' }` on a prop or template (a box, or with `circle`), and a custom property `layer` on a `col_` mesh or `collider` object in a level. Same `passes` rule as `collision.addBox`; a non-text layer on a level wall warns `level-layer-ignored`, a layer on a tilted prop `content-layer-ignored` (collider3d has no layers), and either one then stops every mover.
- A glTF node authored hidden with `KHR_node_visibility` (`visible: false`) now loads hidden (three 0.187 ignores the extension); its children are hidden with it. `threedog assets check` lists such nodes in one `hidden` line per file.
- `engine.hud.hint(id, { action, label, anchor })` (UI part `hud.hint`, @experimental): an on-screen key hint "E · Talk" (written like the interaction prompt). The key text is `engine.input.label(action)`, so it follows rebinding and keyboard / pad switching, and an action that needs a key and has none shows the `input.noKey` text, as the prompt does; `hud.button` takes `action` too and shows its key.
- `engine.hud.button(id, { label, run, icon, anchor })` (UI part `hud.button`): a clickable HUD button. The press never reaches the game (no shot, no look-drag, no pointer lock), focus goes back to the game after a click, and `label` goes through `engine.t`. `hud.remove(id)` takes it away.
- With `nav()` installed but no navmesh (procedural terrain has none, a level may still be loading), `characters.findPath` / `findPathAsync` still use collision A*, and dev builds now warn once (`nav-fallback`) saying so. Which method answers is unchanged.
- `followCamera` keeps distance and pitch inside `minDistance`..`maxDistance` and `minPitch`..`maxPitch` as before, and now warns once in dev when a game asks for a value outside, naming the option to widen (`[camera-clamped]`). The same for a `rtsCamera` start height and a `firstPersonCamera` start pitch.
- `engine.describe().warnings` (dev): every warning said on the page, `{ count, list }` with the first 20 as `{ code, text, fix }`, so an AI sees a fallback or clamp without the console. Codes for "the engine used something other than what the game gave" end in `-clamped`, `-fallback`, `-ignored` or `-replaced`.
- `threedog scenario` / `verify`: a `press` step fails when a game action is blocked (an open window holds input, and the message says who), instead of passing with nothing pressed. A page reload during the run fails it with the reason. `until` is checked inside the page, so it no longer costs one round trip per tick.
- `threedog scenario|verify <name> --freeze-reload`: the dev server ignores file saves during the run (no page reload; a saved `index.html` still reloads), and takes them again when it ends (10 minutes at most). The reload error of a run points to it.
- `threedog dev` fetches the game page once after it starts and prints one line with the status and the next step when it is not 200.
- `threedog perf --size WxH`: measure at a given window size.
- Rule R33 finds a world model by the nearest binding of the name (scope-aware), not any variable of that name in the file. Rule R18 no longer reads a game doc's own helper names as engine API claims.
- `threedog assets check` notes (one information line per kind, not a warning; `--full` lists all) when a model's node name is one three.js GLTFLoader renames (`Wall.001` -> `Wall001`, `_1` suffixes), because `engine.assets` finds the part by the renamed name.
- `scripts/check-public-export.mjs [dir]` (repo maintainers): exits 1 naming internal records (`HANDOFF.md`, `docs/plans/`, test records, `games/`, ...) that git tracks in the public copy; for its pre-push hook.
- Performance you can see: `engine.budget.notice()` (also `describe().perf.notice`) is one line, printed by `describeText`, `threedog shot` and `threedog verify`, when the game is over limits it declared itself (never the engine's own reference limits), slower than its recorded baseline, has a spiky module (p95 over 3x its median and over 2 ms), or runs at a resolution adaptive resolution lowered; nothing when all is fine. `shot --save-baseline` / `verify <name> --save-baseline` write this machine's `.threedog/perf-baseline.json` (`engine.budget.record()`, keyed by GPU, canvas size, pixel ratio and camera; not committed, new games ignore `.threedog/`); later runs with the same key compare medians past a noise margin, modules that were 0 or new included. Budget limits take `modules: { terrain: 1.5 }` (ms per frame of one module).
- `engine.profile()` now returns `{ module: { ms, mean, p95 } }` per frame over the last 300 frame-hook cycles (ms is the median; it used to return the average and reset on read) and is on by default in dev builds; `profile(true)` still turns it on in production. Upgrade: read `.mean` where you used the number. `threedog inspect perf` lists the five dearest modules with p95. Meaning change, same keys: frame time `cpuMs` in `describe().perf`, `inspect.perf()`, the budget and the F3 panel is now one reading, the median of the last frames (`describe().perf.cpuFrames`), where it was the last frame (the panel: a half-second average); it is still 0 before the first frame and null while halted. `describe().perf.cpu` is still the last frame by phase.

- Particles: `ratePerMeter` (effect option, option of `particles.attach`, live on the handle) emits per meter the emitter moves, spread along the path of the step, on top of `rate`. Default 0.
- Particles: `soft` fades a particle where it meets what writes depth, default 0, off. On WebGLRenderer it costs a depth-only draw of the scene per render while a soft effect is on screen; on WebGPURenderer's WebGL2 backend it works only with post and antialias on, and warns otherwise.

## 0.7.1 (2026-11-05)

Never on npm: it reaches users inside 0.8.0. Bug fixes for asset lifetime, WebGPU memory and `assets optimize`, plus new optional tools; nothing public was removed. Upgrade notes are in `docs/MIGRATING-0.8.md`.

- Lighting (changes every game's default look under a sky): the style's ambient column is now the whole diffuse fill. - Post effects: a listed effect is on. `lut`, `grain`, `vignette`, `chromatic`, `dof`, `ao` and `outline` no longer default to `enabled: false` (placed in `style.post` they silently did nothing); pass `enabled: false` to list one off. `style check` counts on-effects by the same rule.

### Fixed

- Interactions: an interaction on a model the game moved away from its world record is found where the model stands (was missed beyond 2 m). One xz index keyed by each item's world position, re-filed only when it moved.
- Scene delta (cascades, fog, glow): a class with its own `material` accessor (troika-three-text) keeps it; the engine's material-swap hook calls the original getter / setter instead of shadowing them.

### Saves

- 0.2 saves load. The calendar takes the old `sky` part (`movedFrom`); saved NPC `talk` fields become `interact`; the `world` part is version 5 (migrated on load). 0.2 builds refuse 0.3 saves as `'tooNew'`.

- Physics: new save part `rigid`. - Error summaries (the dev log's repeat line, `threedog errors`, play / verify / test results) keep the end of a long message, where engine errors put the requirement and `[code]` (was cut at 100–220 characters).
- `new-game` starts blank; `--open-world` gives terrain, sky, follow camera and a player.
- Added: `threedog stress`, `tune show | write`, `gallery [--shots]`, `art list | copy`, `content add | remove`, `--gpu` / `--software`, `doctor --json`, `map -w <game>`. `threedog shot` prints the look numbers after every shot (`--ref`, `--no-look`, `--json`).

Glare is printed as `fact:` with the detail lost under it (on vs off), a `contradiction:` only where DESIGN.md says no glare (`Look intent: no-glare`).
- Look check: large clipped areas, large near-black areas and a night not dark from lighting (`clipped`, `crushed`, `time-flat`) are now `fact:` lines, a `contradiction:` only where DESIGN.md declares the opposite. - content-check: fields of props, templates, pickups and kinds; model names from the game's `assets.js`; old NPC `talk` and `'synth'` sound rules are errors. Rules R41–R45 (engine code); R39 removed.
- Template: a new game's package.json depends on `@threedog/post-effects` (the style's `post` line uses it); the outside-the-repo check installs exactly the template's dependencies.
- Template: a new game has the `shot`, `types`, `perf`, `bake`, `assets` and `doctor` scripts the docs name (`npm run shot` works in a standalone game).

- Look check: a `light:` fact (key vs fill share of the brightness, how much darker shadows are; a contradiction only under a DESIGN.md "strong / dramatic light"), a fact when the camera stands inside a closed mesh, each exposure next to noon / midnight when a style's exposure curve differs; the printed block is short (at most four one-sentence hints, ranked; `--json` keeps all).
