# Moving a game from 0.9 to 1.0

First run `threedog doctor --fix`, then `npm run check`: a removed name shows up as a type error on the line that uses it. Most games need nothing else. The tables say what you will see and what to do, and every error below names its own fix.

## What now stops with an error

| You will see | What changed | What to do |
|---|---|---|
| A game's own vehicle loses its rider after a load in a fresh session | Saved riders find vehicles through one registry, not through `rigid` | Call `engine.characters.addVehicle(vehicle)` once it is built, before or after the load |
| `exit()` returns `false` and the rider stays | No exit of the vehicle is walkable | Move the vehicle, offer more exits through `exitPosition(seat, n)`, or `exit({ force: true })` |
| `walkTo` answers `'cancelled'` after `placeAt`, `enter`, a level change or a ragdoll | Each of them ends the walk. It used to carry on, or wait under the ragdoll | A follower that wants to go on after being placed calls `walkTo` again |
| `walkTo` ends `'noPath'` before a gap where it ended `'stuck'` at it; small bodies take gaps they used to go round; a stall the first time a new size asks | Navmesh paths fit the radius that asks, on a mesh of that size built on first ask | Drop an `agentRadius` set to the widest walker unless `crowd: true` needs it. Ask once per size during loading to move the stall there (recipe 12 section 5) |
| `[shared-taken]` at `engine.use(...)`, naming `terrain` and `level` | `ground` is one exclusive slot. The later `setGround` used to win | Keep one, or swap with `engine.use(level(), { replaces: 'ground' })`. To run both: `terrain({ part: true })`, `level({ part: true })` and `compositeGround({ parts: [{ of: 'terrain' }, { of: 'level', region }] })` |
| `[shared-taken]` for any other slot, in a release build too | A second provider of an exclusive slot is refused in every build. A release build used to warn and let the later one win | Install one, or `engine.use(mine(), { replaces: 'slot' })` |
| `[shared-conflict]`, in a release build too | Two owners `set` one point on one layer. A release build used to warn and let the later write win | Contribute with `add` / `mul`, use another `layer`, or keep one owner. The message has each fix to copy |
| `[control-conflict]`, in a release build too | Two owners take one character on one control layer. A release build used to warn and let the later owner win | End the old hold first (`handle.remove()`), or take another layer. The message has both fixes to copy |
| `[container] ... must be a whole number >= 1` | `add`, `remove`, `setData`, `transfer` and `trade` refuse 0, negatives, fractions and NaN. `remove('apple', -2)` used to add stock | Pass a whole number of pieces. To put stock back, call `add` |
| `engine.disabledModules` | Removed: a switched-off module has state `'disabled'`, and one list is derived from it | `engine.describe().disabledModules` |
| `settings({ presets: { low: { viewChunks: 3 } } })` | `viewChunks` and `density` in a preset are shares (0 to 1) of the game's own value, as `pixelRatio` already was; above 1 throws | Write the share, e.g. `viewChunks: 0.6` |
| `engine.post.antialias` with no effect on | It no longer switches the post chain on to reach an MSAA the canvas lacks; MSAA is fixed with the canvas | `createEngine({ antialias })`; the settings row applies at the next launch |
| `settings.set(key)` on a key no row owns | Throws `settings-row` after start; before start it waits for a module's row and warns if none came | Define the row, or add the tab that has it |
| `applyState({ wether: 'rain' })` | A key no installed module names in `stateKeys` is refused in the answer, not thrown | Read `refused` |
| `[module-needs] content quests: no installed module reads this section` | A module owns its content section, and data for a module that is not installed stops the load | Add the module the message names, or remove the data |
| The same error after `engine.use(mine(), { replaces: 'quests' })` | Replacing a module replaces its section too | Give the replacement `content: { quests: { commit(d) { ... } } }` (recipe 14) |
| `[character-option] mover "...": use 'simple', 'rapier', 'manual' or your own` | An unknown mover name used to warn and walk with `'simple'` | Fix the name, or pass `(character, engine) => ({ name, move(x, z, run, dt, y) })` (recipe 57) |
| A player or a body that fell out of the world stays gone, and a dev build says `no rule 'fall' is set` | The engine no longer rescues by default: `character:fall` and the rule `fall` stay, `'rescue'` is a built-in the game chooses. `openWorld` and the new-game templates choose it | `engine.mod('fall', { owner: 'game', set: 'rescue' })`, or `characters({ fall: 'rescue' })`. A deep pit or a death that was fighting the rescue needs nothing |
| `preventDefault is not a function` in a `character:fall` listener | Falling is one rule, `fall`, for characters and rigid bodies | Remove the call. `engine.mod('fall', { owner: 'game', id: 'player', set: false })` leaves the fall to the game; a function `(facts, engine) => 'rescue' \| false` decides per fall |
| `nothing explains 'picture' (did you mean 'value'?)` | `explain({ picture })` is now `explain({ value })`, which also gives the short history | Rename the key. On the command line: `threedog explain value fog.far` |
| `explain is not a function` on a thing | `engine.explain` is the one way to ask why | `engine.thing(id).explain()` becomes `engine.explain({ thing: id }).detail`, and `threedog thing <id>` becomes `threedog explain thing <id> --full` (MCP: `explain` with `about: 'thing'`) |
| `[save-key-taken]` from `saves.define` | A second register on a held key used to take the part from its owner with nothing said, and that owner stopped being saved | Use another key, or `remove()` the first handle before registering again |
| `[skip-busy]` from `engine.skip` | A second skip during a first one's fade used to resolve and unfreeze the game mid-fade. The doc always said it rejects | Await the first skip, then skip again |
| `[save-busy]` from `saves.collect` | A load is running. `saves.save` waits for it, `collect` cannot | Collect after the load. Do not await `saves.apply` or `saves.load` inside a part's `load()` or an `afterLoad`: dev warns `save-nested`, because it would wait forever |
| `setViewChunks is not a function` or `setDensity is not a function` | One entry each: `terrain.viewChunks` and `terrain.density` take effect when written | `terrain.setViewChunks(n)` becomes `terrain.viewChunks = n`; `terrain.setDensity(d)` becomes `terrain.density = d`. Plants that block stand at every density |
| `[save-bad-record]` on loading a save, naming `the level file` or a record `model` | A save may name a registered asset or a relative path on this site, nothing else. A full URL, `//host`, a backslash or `..` used to be fetched | Register a level or model that lives on another host in the asset manifest and name it there: a registered entry passes whatever its URL |
| `setRadius is not a function`, `setAuto is not a function`, `setAntialias is not a function` | One entry each, like `terrain.viewChunks` | `stream.setRadius(m)` becomes `stream.radius = m`, `weather.setAuto(on)` becomes `weather.auto = on`, `post.setAntialias(on)` becomes `post.antialias = on` |
| `threedog eval` is an unknown command | It was a second name for `threedog js` | Use `threedog js` |
| A type error on `engine.moduleStates` | It was experimental and is internal now | Ask `engine.explain({ module: name })`, or read `engine.describe().moduleStates` for what is not running |
| An op that ends in `return e.content.run(...)` fails where it used to pass | `content.run` answers with a failure when a word failed, and an op that returns one fails with it (an atomic one rolls back) | Good if that is what you meant; else do not return the answer |
| A quest with a `give` reward and a full bag says the reward was not given, and pays it later | The items used to be lost. They are owed now | Nothing, or add `onUnpaid` to decide yourself (recipe 04) |
| An async `onUse` on a `once` item is not used up at once, and a second use is refused until it settles | It is judged when it settles. It used to spend the item straight away, whatever came back | Nothing. Read the answer with `await r.value` |
| `const { skipped } = await timeline.play(...)` is undefined, same for `timeline:end` | A run has one ending | Read `ending`: `'finished'`, `'skipped'`, `'dropped'` or `'failed'` (with `error`) |
| A cutscene's remaining `do` steps no longer run at a new game | A new game drops the run, as a load does. It used to skip it, running them on the new state | Put what must happen in `session:end` |
| `[engine-misuse] vars.bump` | `n` must be a finite number. NaN used to go into the counter | Pass a number |
| `[module-params] triggers.add({ radius })` | A NaN or negative radius used to sit in the zone list and never match | Pass a finite number >= 0 |
| `[grids-misuse] grids.add` | A cell, origin or size that is no valid number is refused | Cell > 0, a finite origin, size whole numbers > 0 or left out |
| `[quest-step] ... next` | A step's `next` must be a step of that quest or a function | Fix the id the message quotes |
| `[save-version]` at `saves.define` | A `migrate` key must be a whole version below the current one | Rename the key |
| `saves.save` answers false with `[save-part-threw]` | A part's `save()` returned a function, a symbol, NaN or an infinity, which a save cannot hold | Return plain data, or null for nothing |
| `[save-write]` from `saves.putAttachment` | Only a Blob is stored | Pass a Blob |
| `[terrain-option]` from a terrain edit | An edit that would touch more than about four million points is refused | Use a smaller radius or several edits |
| `[rigid-misuse] ... differs between axes` | A body cannot follow a parent scaled unevenly | Make the parent's scale equal on all axes |
| `[bad-position]`, `badArgs`, `[world-add]`, `[world-id]`, `[interaction-option]`, `[content-template]`, `[content-place]`, in a release build | These checks ran only in development. A game that passes its development run sees none of them | Fix what the message names |
| The contract check fails on a replacement's own `contract.js` that lists `methods` | Object contracts (`mover`, `vehicle`, `ground`, `collider3d`) list their members under `api` like every other contract | Rename `methods` to `api` |
| `module-order` from `use()` for an order written with a capability name | The same order by module name always threw | Put the provider in the stage the order needs (`stage: 'environment'`), or drop `before` / `after` from the module that says it |
| `engine.detach is not a function` | Removed: it only called three.js | `obj.removeFromParent()`. `engine.remove` stays |
| `Cannot set property locale` on `engine.i18n` | `locale` is read-only. Writing it skipped the name lookup and `i18n:change` | `engine.i18n.setLocale(name)` |

## What now behaves differently, with no error

- A `level.load` or `content.load` inside a save part's `load()` or a module's `afterLoad` needs the turn they get: `load(d, turn) { return engine.level.load(d.level, { turn }); }`. Without it the call waits for that load to end, so awaiting or returning it never ends (dev: `[save-nested]` after 3 s). Calls that are not awaited run right after the load.
- A save part registered while a load runs gets its data after that load, not during it. Idle it is still before `register` returns.
- `content.load` returns a Promise of this load instead of `engine.content`. Chain with a second statement: `content.load(a).load(b)` becomes two lines. Bad data still throws on the line; a pack with nothing to wait for is still live on the next line.
- A pack that swapped the level and then failed now rejects, after the old level is back, where it used to throw at once while the old level loaded in the background. Read the failure with `await` or `.catch`. A failed restore is on `err.notRestored`.
- A collision module that throws from `addBox` while taking the level walls now fails its `use()`, and the module it replaced comes back. An old `engine.haltLoop` or `views.show` handle removed after a new one was taken does nothing.
- `world.simulate` with `channel`: `far` and a tiered `near` get the channel time the record lived through, not the seconds owed times the speed at that moment. Remove anything written to work around a far `dt` that followed the last speed. The world save part gains `marks`; older saves load without it.
- A level file that fails rejects even when the manifest gives it a fallback; a level never stands on a stand-in. Nothing to write unless a game relied on the gray box.
- `engine.loading.timeoutMs` is now the limit on every load, on each module's `init()` and on every wait for "settled", not only on `isReady`. A file with no sign of life for that long fails like any failed file. Raise it for a load that is silent for longer than 120 s.
- `flow.transition` rejects with `module-not-ready` when the world does not settle within the limit. The screen and input come back first. Catch it if the game has an answer.
- `level.load` during `saves.load`, `saves.apply` or a `session` call runs after it, so the level the load answered true for stands first. Do not await it inside a part's `load()` after an `await`: that waits for itself.
- Autosave does not fire during `flow.transition` or `timeline.play`; it fires on the first step after. A save the game asks for itself still goes at once.
- `content.load` during a state replacement commits after it.
- The `level` save part of a level built in code holds a token only that page can read. From another page the load stays on the level that stands, as before.

| You will see | What changed | What to do |
|---|---|---|
| An unhandled rejection from `level.load` | The new level is built first. On failure the old one stays, `level:failed` fires instead of `level:loaded`, and the Promise rejects | `await` it in a `try`, or add `.catch`. A save that names a broken level now rolls back |
| `ops.run` / `ops.can` / `ops.undo` answer `'loading'` | They change nothing for the whole of a state replacement, including a part's `load()` and `afterLoad` | Retry after the load: `await` it, or wait for `save:loaded` |
| A game's `applyState` hook no longer gets `?weather=rain` from the URL | Only core's own keys and the keys a module names in `stateKeys` are read from the URL. A hook with no `stateKeys` still gets such a key from a direct `applyState({ weather: 'rain' })`, but with the module that owned it absent, nothing reads it from the URL | Name the key in your module: `stateKeys: ['weather']` |
| A second `saves.apply` or `saves.load` waits | Overlapping loads now take turns and end as one whole save | Nothing, unless you relied on the second one starting at once |
| A `control.take` on a script, cutscene or physics layer, or a `world.anchor` set during play, stayed after a new game | Both end with the playthrough; `world.anchor` goes back to what boot left | Take or set it again from a `session:start` listener, or take the hold through `ctx.control` when it belongs to a module |
| `saves.load` or `saves.apply` left the title open | Any save put back closes it, and a rollback fires `session:failed` with `kind: 'quick'` | Drop your own `ui.close('title')`; a `session:failed` listener that only meant `session.*` checks `kind` |
| Code that looked for the freeze owners `threedog:load` / `threedog:load-parts` finds nothing | They are one owner now, `threedog:state-replace` | Wait for `save:loaded` |
| `thing.set`, `world.set` or `world.move` on the player or an NPC with a model now really moves it, and it lands on what stands there | The character owns its position, so these writes are its `placeAt`. They used to return ok and change the record until the next step put it back. A write that matches where the character stands changes nothing | Remove any `placeAt` you added beside such a write. To set the exact spot, `root.position` then `syncRecord()` from a control hold (recipe 57) |
| A seated character gets out when it is placed: `vehicle:exit` fires and the vehicle brakes | `placeAt`, `engine.stream.teleport` and any write to its record's position end the ride. The seat used to pull it back on the next step | To take the rider along, move the vehicle. To keep a stale position write from ending a ride, drop the write. Undo of such a `thing.set` seats it again, and can answer `ownerRefuses`: read the result |
| `placeAt` or a position write on a ragdoll moves the whole body, which stays limp | The next step used to put root back on the body. It arrives at rest, so a fall's speed is dropped | To stand it up elsewhere, `remove()` first as before; the result is the same |
| `rot` or `scale` on a live character's record turns or sizes it, and `thing.set` keeps all of `rotation` / `scale` given as `[x, y, z]` | They used to land on the record and do nothing, and the array forms kept only y and x. A tilt, a turn while seated or a value that is not a number or `[x, y, z]` is refused: `thing.set` answers `ownerRefuses`, `world.set` throws `[character-option]` | A field of your own called `rot` or `scale` on the player or an NPC needs another name |
| A write to a record with `positionFrom: 'view'` moves its model and rigid body, which comes to rest there | `world.move`, `world.set`, `thing.set` and `rec.position` used to be overwritten by the model at the end of the step. `rot` or `scale` on a template with a `body` now rebuilds the body | Drop a write that relied on being ignored; to push a body, use `rigid.impulse` |
| `engine.use(mine(), { replaces })` receives the old module's save data | A save part that leaves keeps its data and hands it to the next part with that key | Give `mine` its own key if the format differs |
| A module waits as `'blocked'`, with no `init` and no hooks | `requires` means the provider works, not only that it is installed | `engine.explain({ module: name })` says on what |
| The flat ground returns when a ground provider leaves | `ground` belongs to the module that holds the slot | A module of your own declares `provides: ['ground']` and calls `ctx.ground.provide(...)` |
| Paths are `{ x, y, z }` | `findPath`, `findPathAsync` and `engine.nav` keep the height | Read `y` if your game has floors; code that reads `x` and `z` is unchanged |
| With two engines on a page, only one reacts to a key or a gamepad | The engine last pressed or focused owns the keyboard and the gamepads, the first one until then. Both used to hear every key and pad | Nothing with one engine. To hand the keyboard over from code, focus something in that engine's `uiRoot` |
| The wheel changes the view height of a real `OrthographicCamera` under a default follow rig | It used to change `distance`, which shows nothing there | Nothing |
| `engine.camera` is another object after a rig or shot with `projection: 'orthographic'`, and `camera.orthoSize` and `camera.isEngineCamera` read `undefined` | The engine's first camera is a plain `THREE.PerspectiveCamera`. An orthographic view is now always a real `THREE.OrthographicCamera` in `engine.camera`, and the next perspective view brings the first camera back. It has no `fov` or `aspect` | Read `engine.camera` where you use it, not from a copy kept across a switch. The view height is `camera.top - camera.bottom` or `describe().camera.orthoSize` |
| `projection: 'orthographic'` over a real perspective camera you assigned works | It used to throw `[camera-option]`. The rig's own orthographic camera stands in until the next perspective view, which brings yours back | Nothing |
| With two tabs open, `saves.remove` keeps a slot and `putAttachment` / `removeAttachment` reject with `[save-stale]` | They follow the rule saves already had: a tab changes only what it last wrote or saw. A forgotten tab used to delete or replace newer progress | Nothing for one tab. On the rejection read `saves.attachments(group)` first, or use another id |
| A settings row or tab is gone after `engine.unuse` | A row or tab a module made in its install, init or a hook leaves with that module and gives its limits back. It used to stay, driving nothing | Define a row that must stay from the game, not from the module. The player's choice comes back when the module does |
| `findPath` without `nav` says `noPath`, and `walkTo` ends with that status | A goal on a floor the walker cannot reach used to be `ok`, with a path that ended under it | Handle `noPath` |
| `threedog how --list` is gone | `threedog how` or `--browse [category]` to browse, `--card <id>` for one capability. The MCP tool takes `browse` and `card` fields; `task: "--list"` is only words now | Use the new flags |

Everything else since 0.9.0 is new and opt-in, or changes nothing for a game: `CHANGELOG.md` has the full list.
