# engine.characters — characters(opts?: CharactersOptions)

Characters: addPlayer() (characters() module)

- Options `CharactersOptions`:
  - `npcs?: boolean` Whether to enable NPCs (engine.npcs), default true
  - `npcTiers?: { fullRadius: number; nearEvery: number }` (experimental) Near tiers for large NPC crowds, off by default (every near NPC walks every fixed step); same as engine.npcs.tiers(opts)
  - `fall?: 'rescue' | false | ((facts, engine) => 'rescue' | false)` The rule 'fall' for everyone: 'rescue' brings what falls out of the world back; left out, the engine rescues nothing. engine.mod('fall', ...) from the game sits above it
  - `animation?: AnimatorOptions` What every character's Animator starts from, e.g. { fade: 0.15 }; a model's manifest mapping and the character's own animation win over it

## Methods and properties
- `characters.findSpawn(position?: PositionLike, opts?: FindSpawnOptions) → Vector3` — Find a spawn point: searches outward from position (default origin) for walkable (not steep, no obstacle), non-water ground, without assuming terrain height; e.g. findSpawn(v, { minH: 3, maxH: 20 }). Returns a Vector3 (y is the ground height)
- `characters.addPlayer(opts: PlayerOptions) → Character` — Create the player and set engine.player; control is required (no default feel), e.g. addPlayer({ ...presets.player.thirdPerson, spawn }). An existing player is deleted first
- `characters.moveInput(seat?: Seat) → { x, z, run }` — The 'camera' player control as a value: keys / stick relative to the camera, the 'run' action if bound, input.autopilot. Reused object; call it inside your own control function to wrap it
- `characters.addVehicle(vehicle: any) → { remove(): void }` — Join the vehicles a saved rider can be seated in again, before or after the load
- `characters.support(object: any, opts?: { id?, safe?, carry?, inherit? }) → { id: string; remove(): void }` — Something characters stand on and ride (moving platform, lift, raft). Move the object any way (onFixed before or after the player, a timeline, physics): riders follow how its matrix changed, so the order does not matter. safe: false = never a respawn spot; carry 'position+yaw' turns riders with it; inherit: false = jumping off keeps none of its speed. With mover 'rapier' give it a collider too. Example: `const lift = engine.characters.support(liftMesh); engine.onFixed(() => { liftMesh.position.y = 2 + Math.sin(engine.time.now('real')); });`
- `characters.removePlayer(id?: string)` — (experimental) Delete the current player (exits the vehicle first, stops responding to keys, fully deletes the model). The player save (key player) carries the position and the vehicle; loading an on-foot save exits the vehicle first
- `characters.findPath(from: PositionLike, to: PositionLike, opts?: FindPathOptions & { detailed?: false }) → NavPathPoint[] | null` / `findPath(from: PositionLike, to: PositionLike, opts: FindPathOptions & { detailed: true }) → PathResult` — Pathfinding (the single entry point): uses the navmesh when nav is installed and ready, otherwise the A* fallback. Returns a path [{ x, y, z }...], or null if unreachable
- `characters.findPathAsync(from: PositionLike, to: PositionLike, done: (path, status) => void, opts?: { radius?, passes?, step?, maxNodes? }) → { remove(): void }` — findPath for many callers (NPC crowds, AI squads): solved in engine.threads workers; done(path, status) runs on a fixed step a few steps later (same paths with threads on or off). Recipe 12 section 4
- Properties:
  - `material: Material` The three.js material of every placeholder capsule. Set it to swap the look of all of them at once; used as given, with no patches added. A character with colors.body draws with a copy of it in that color. A model's own materials are the model's. Example: `engine.characters.material = new THREE.MeshToonMaterial({ color: 0xd9a066 });`
  - `kit: { beginMove, groundAt, endMove, ownState }` What a game's mover calls to take part in contact, each optional (recipe 57): a mover calling none owns contact itself (beginMove() groundAt() endMove() ownState())
  - `pathsPerStep: number` How many findPathAsync requests leave per fixed step (default 32); the rest wait for the next steps
  - `linkPose: ((t, position, crossing, character) => void) | null` (experimental) Bends a link crossing away from its straight line: t 0-1, called each step after position is set on the line, write to position. Depends only on its arguments, so a crossing saved halfway resumes on the same curve. null = the straight line

## Character (engine.player / NPC are both Character)
- `player.push(vx: number, vz: number, seconds: number)` — Move at a fixed velocity (m/s) for seconds, ignoring move()'s direction and without turning (knockback, dodge roll); gravity and collision still apply
- `player.stat(name: 'speed' | 'runSpeed' | 'gravity' | …) → number` — A movement stat as the mover uses it now: the base field with every engine.mod('move.<name>') entry applied (canJump reads 1 / 0). Example: `engine.mod('move.speed', { owner: 'haste', id: 'player', mul: 1.2, for: 5 }); player.stat('speed')   // 1.2 x player.speed`
- `player.addJumps(n?: number)` — (experimental) Give back n jumps for this airtime (pickup, wall touch)
- `player.resetJumps()` — (experimental) All jumps back, as if it had landed
- `player.launch(speed: number, opts?: { owner?: string })` — Throw it upward at speed m/s (jump pad, spring): leaves the ground, ends coyote time, the ground jump counts as used (air jumps stay); emits character:launch. Example: `player.launch(19, { owner: 'pad' })`
- `player.jumpState() → { grounded, coyoteLeft, bufferLeft, jumpsUsed, jumpsLeft, vy }` — (experimental) Jump state now, read-only
- `player.enter(vehicle: Rideable)` — Board a vehicle (rigid.addWheeled's, or any object with the vehicle contract): the driver seat when free, else a free passenger seat; no-op when full
- `player.exit()` — Exit the vehicle
- `player.playAction(name: string)` — Play a one-shot action (e.g. 'wave'); skipped if the model has no such clip
- `player.onPose(fn: (character, dt) => void) → { remove(): void }` — Run fn(character, dt) every frame right after the animation pose is applied (model clips or procedural rig): attach things to bones or adjust bones. h.remove() stops it. Presentation only. Example: `const h = player.onPose(() => sword.position.copy(hand.getWorldPosition(v)));`
- `player.dispose()` — Fully delete this character: exits the vehicle first, releases animation and movement, removes it from the scene and releases geometry and materials (used by npcs.remove / removePlayer)
- `player.jump(opts?: { air?: boolean })` — Request a jump (buffered for jumpBuffer s): the ground jump on the ground or in coyote time, else an air jump while maxJumps allows; air: false = ground only. Example: `addPlayer({ ...presets.player.thirdPerson, maxJumps: 2 })   // double jump`
- `player.placeAt(position: PositionLike)` — Put it on the ground at position (Vector3 / object / [x, y, z] / { x, z })
- `player.syncRecord()` — After moving root yourself (a cutscene path, a scripted pose): write position and motion back to its world record (the player's), so a save right after has it
- `player.walkTo(target: Vector3 | { x: number; z: number } | [number, number, number] | …, opts?: { speed?, arrive?, turnRate?, stuckSeconds?, maxRepaths?, run? }) → Promise<{ status: 'arri… & { remove(): void }` — Walk to a point along characters.findPath on fixed steps; never rejects. One walk per character: a new walkTo, dispose() or a save load ends the old one with 'cancelled'. Transient: not saved, not fast-forwarded by engine.skip. Holds the character's control on layer 'script' (owner 'walkTo'): the player's keys / an NPC's schedule pause meanwhile, a cutscene pauses the walk, and another script owner on it is control-conflict
- `player.move(dirX: number, dirZ: number, run: boolean, dt: number, dirY?: number)` — Move in a direction (called once per fixed step): dirX/dirZ is the world direction (length 0–1 scales the speed), run to run, dt in seconds (used as given). Speed comes from the stats: engine.mod('move.speed', { owner, id: character.id, ... }) (the player: id 'player'), the one way to change speed. A character someone controls (engine.control.of(ch)) moves only through its holder: called from anywhere else it is control-bypass in dev; take control and use handle.move() / step instead
- `player.groundType() → string` — Ground type underfoot ('water' while swimming)
- `player.face(target: PositionLike | number)` — Turn at once to a position, or to an angle in radians (0 = +Z)
- `player.saveMotion(out?: CharacterMotion) → CharacterMotion` — (experimental) Copy the motion state into a plain object (velocity, vertical velocity, heading, movement amount, grounded, swimming) to store in world data; after the model is rebuilt or a save is loaded, loadMotion continues from it with identical results
- `player.loadMotion(m: CharacterMotion | null | undefined)` — (experimental) Restore the motion state from the plain object of saveMotion
- Properties:
  - `root: Object3D` Root node, the character's model (there is no character.model; the loaded glTF is a child of root): add it to the scene with engine.add(character.root) when you built the Character yourself; add children, change visible and scale on it
  - `position: Vector3` Position (= root.position)
  - `velocity: Vector2` Horizontal velocity (x, y map to world x, z). Writable: a write is an impulse the mover steers back toward the input (lasting knockback: push(); full control: mover 'manual')
  - `facing: number` Heading (radians): 0 faces +Z, forward = (sin facing, cos facing); increasing turns toward +X (rotation about the Y axis, consistent with root.rotation.y)
  - `vy: number` Vertical velocity (m/s), kept apart from velocity, which is horizontal only (velocity.y is world z, not this). Writable: setting it is an impulse (launch() does the same and also leaves the ground cleanly)
  - `grounded: boolean` Whether standing on the ground
  - `swimming: boolean` (experimental) Whether swimming
  - `state: CharacterState` Current action state
  - `moveAmount: number` Current movement speed (m/s)
  - `faceMode: FaceMode` Facing mode, change at any time; see CharacterOptions.faceMode
  - `faceTarget: PositionLike | null` What faceMode 'target' faces
  - `cameraFollow?: boolean` (experimental) Player only: whether the camera module follows it (see PlayerOptions.cameraFollow)
  - `swimDepth: number` (experimental) 
  - `swimSpeedFactor: number` (experimental) 
  - `turnSpeed: number` (experimental) 
  - `acceleration: number` (experimental) 
  - `stepHeight: number` (experimental) 
  - `airControl: number` (experimental) 
  - `coyoteTime: number` (experimental) 
  - `maxJumps: number` (experimental) Base jump values (the game's; modifiers go through engine.mod('move.jumpSpeed'))
  - `airJumpSpeed: number | null` (experimental) 
  - `jumpBuffer: number` (experimental) 
  - `fall: false | { belowY }` (experimental) Fall check (see CharacterOptions.fall); a plain property
  - `channel: string` Time channel the engine drives it on (see CharacterOptions.channel)
  - `passes: readonly string[] | undefined` Collider layers it goes through (the passes option, sorted); undefined = stopped by every collider. Plain: a write counts from its next step and path
  - `id: string` The character's id, the one form engine.mod / time.local take: its world record id ('player', an NPC's record id), else the id option, else a generated one
  - `support: { kind, object, id, safe, velocity }` What it stands on, read-only (reused object); 'platform' = a registered support (characters.support), which carries it
  - `safeGround: Vector3 | null` Last spot it stood still on safe ground (where a fall returns it); null until it first stands. Saved with the motion
  - `mover: { name, controller?, body?, collider?, move, dispose?, … }` How it walks now; name is 'simple' / 'rapier' / 'manual', controller is the native Rapier character controller (when rapier). Assign a name to switch: c.mover = 'manual'
  - `anim: Animator | null` Skeletal animation state machine (when there is a glTF model; null while a model named by asset is still loading)
  - `ready: boolean` false while a model named by asset is loading (the placeholder body shows); true otherwise, also after a failed load (placeholder kept)
  - `whenReady: Promise<void>` Settles (never rejects) when a model named by asset is swapped in or has failed; already settled otherwise. Example: `const npc = new Character(engine, { model: 'villager' }); engine.add(npc.root);   // import { Character } from 'threedog' await npc.whenReady; npc.playAction('Wave');`
  - `vehicle: Rideable | null` The vehicle it sits in (null on foot)
  - `seat: number | null` Its seat in the vehicle: 0 drives, others ride; null on foot

## NPC (engine.npcs.add() returns an NPC (extends Character))
- `npc.setBehavior(name: string, mind?: Record<string, any>)` — Change behavior (stored in the data, restored by saves). mind is the new behavior's parameters / memory (plain values), cleared if omitted. E.g. npc.setBehavior('wander', { radius: 12 })
- `npc.currentStop() → ScheduleEntry | null` — The stop it should be heading to now
- `npc.placeAt(position: PositionLike)` — Teleport to the ground at a position (handed to the mover when there is a model, otherwise the data is changed) and re-pathfind
- `npc.face(position: PositionLike)` — Face a position (when there is a model)
- `npc.remove() → boolean` — Delete this NPC (data and model together)
- Properties:
  - `id: string` Stable id
  - `data: WorldRecord | undefined` The record in world (a plain object; undefined after deletion). Change fields with engine.world.set(npc.id, {...})
  - `schedule: ScheduleEntry[]` Schedule (at converted to 0–1, sorted by time)
  - `behavior: string` Current behavior name
  - `interact: { label, op, args, radius } | null` What the interact key does near it ({ label, op, args, radius } as saved), null when nothing
  - `state: string` Animation state ('idle' / 'walk'...)
  - `busy: boolean` In dialogue (stopped, not walking)
  - `character: Character | null` The current character model: exists only when nearby; null when far away, in another level, or not yet built
  - `root: Object3D | null` Root object of the current model (= character.root), null when there is no model
  - `object: Object3D | null` Same as root
  - `position: Vector3` Position: the model's position when there is a model (use it read-only, move with placeAt), a copy of the record's position when there is none

## Data structures
- **NPCOptions** (extends CharacterOptions) Parameters of engine.npcs.add({...})
  - `id?: string` Stable id (used by saves, quest targets { npc } and npcs.get); falls back to name if omitted (two NPCs with the same name and no id throw an error). Calling add again with the same id updates the definition and keeps position and state
  - `initial?: boolean` NPC authored in content (everything added by content): the initial record of world; saves only record changes such as position and state, the schedule follows the content; deleted ones do not reappear after loading
  - `name?: string` Name
  - `zone?: string | null` Which zone it belongs to (a level name, see world.zone): when not in this zone only the model is torn down and the data stays; null (default) means it is present everywhere
  - `schedule?: ScheduleStop[]` Schedule (needs the sky module; without it the first entry is always used)
  - `behavior?: string` Behavior name: 'schedule' (default, follows the schedule), 'wander' (roams around home) or a name registered with npcs.behavior()
  - `mind?: Record<string, any>` Behavior parameters and memory (plain values, saved). wander: { radius in meters (8), pause [min, max] seconds ([2, 6]), home { x, z } (defaults to the position when wandering started) }
  - `interact?: NpcInteract | null` What the interact key does near it (needs interactions()): runs the op with { npc: id, ...args }. Dialogue is one such op: { op: 'npc.talk' } (script defaults to the NPC id; args: { script } names another, { channel: 'bubble' } plays it as lines over the NPC while play goes on). Example: `interact: { op: 'npc.talk' }`
  - `pathStep?: number` Pathfinding grid size (meters), default 2
  - `repath?: number` Seconds before re-pathfinding after getting stuck, default 2
  - `arriveDistance?: number` Arrival distance (meters), default 1.2: within 1.2 m of the schedule stop / target counts as arrived and stops, it does not step exactly on the point (call placeAt yourself for an exact spot)
  - `position?: PositionLike` Initial position (Vector3 / object / [x, y, z] / { x, z }); the current schedule stop is used if omitted
- **ScheduleStop** One schedule stop (the npcs.add form): at is when to set off, position the destination
  - `at: number | string` When to set off: clock time 'HH:MM' (e.g. '18:30'), or a time of day 0–1 (0.25 = 6 am)
  - `position: PositionLike` Destination (Vector3 / object / [x, y, z] / { x, z })
- **ScheduleEntry** One schedule stop (as stored in npc.schedule after install): at has been converted to 0–1, x/z is the destination (meters)
  - `at: number`
  - `x: number`
  - `z: number`
- **PlayerOptions** (extends CharacterOptions) Parameters of addPlayer()
  - `id?: string` A further local player's id and world record; left out, the one player (engine.player)
  - `input?: Seat` The seat that drives this player (engine.input.seat); default engine.input
  - `spawn?: PositionLike` Spawn point (meters, { x, z } / Vector3 / object); flat ground is found automatically if omitted
  - `control: PlayerControl` Required, no default: 'camera' (keys relative to the camera) / (player, input, dt) => ({ x, z, run? }) (null stands still). presets.player.* fill it. Given once: a game that steers the player for a while takes control (engine.control.take(player, { owner, layer: 'script', step }))
  - `cameraFollow?: boolean` true: the camera module follows the player (and back after a vehicle, and on a new session). Omitted with a camera installed warns in dev
- **CharacterOptions** Character parameters (shared by the player and NPCs)
  - `colors?: { body?, skin?, legs?, hair? }` Per-character part colors: recolor the body's meshes marked userData.part (a humanoid rig: body, skin, legs, hair)
  - `speed?: number` Walking speed (m/s), default 4.5
  - `runSpeed?: number` Running speed (m/s), default 7
  - `radius?: number` Collision radius (meters), default 0.4
  - `water?: CharacterWater` What water deeper than swimDepth does: 'swim' (default: floats, state 'swim') / 'block' (never enters it) / 'wade' (walks the bottom) / a function deciding per spot (a swim skill, a boat, depth). character:water fires on each change
  - `states?: CharacterStates | null` The game's own states on top of the built-in ones (crouch, climb, glide, dash, roll): run after the mover's state each step, return a state name or null to keep facts.base. The state picks the clip like any other (clips: { crouch: 'Crouch' }); speed changes stay engine.mod('move.speed'). Example: `addPlayer({ ..., clips: { crouch: 'Crouch' }, states: (c, f) => f.grounded && engine.input.down('crouch') ? 'crouch' : null })`
  - `swimDepth?: number` Water depth (meters) at which water counts as deep, default 1
  - `swimSpeed?: number` Swimming speed multiplier, default 0.45
  - `turnSpeed?: number` How fast it turns, default 10
  - `acceleration?: number` How fast it starts / stops, default 12
  - `gravity?: number` Gravity (m/s², negative), default -24
  - `jumpSpeed?: number` Jump speed (m/s), default 8
  - `stepHeight?: number` Step height it can climb directly (meters), default 0.45
  - `airControl?: number` Air control, 0–1
  - `coyoteTime?: number` How long after walking off an edge a jump is still allowed (seconds)
  - `canJump?: boolean` Whether it can jump, default true (stuns and cutscenes use engine.mod('move.canJump', { owner, id, set: 0 }) instead of writing it)
  - `maxJumps?: number` Jumps before landing again, default 1; 2 = double jump (jump() again in the air)
  - `airJumpSpeed?: number` Takeoff speed of an air jump (m/s), default jumpSpeed
  - `jumpBuffer?: number` How long a jump() pressed early waits for the ground (seconds), default 0.12
  - `fall?: false | { belowY }` Falling out of the level: below belowY (or when belowY(character) is true) character:fall fires and the rule 'fall' decides: back to safeGround by default, engine.mod('fall', { owner, id, set: false }) leaves it to the game. false (default) = off
  - `channel?: string` Time channel its movement and animation follow when the engine drives it (player default 'player', others 'world')
  - `passes?: string[]` Collider layers it walks through, e.g. ['gate'] (collision.addBox { layer: 'gate' }): its walking, walkTo and NPC paths, navmesh included, follow it. Default: stopped by every collider
  - `model?: Object3D | string | null` The body, one path for every kind: the name of a registered model asset, or what engine.assets.model() returned. A procedural builder name (from an asset pack) is built at once; a file model name shows a gray capsule and swaps in a copy when it loads (Character.ready / whenReady, event 'character:model'). Example: `engine.assets.manifest(yourAssets); engine.characters.addPlayer({ model: 'yourBody' })   // a generator or GLB name from an asset pack`
  - `rig?: CharacterRig | null` A ready procedural body (CharacterRig), used instead of model (a hand-built guard / pet)
  - `id?: string` Id for engine.mod / time.local entries of a character without a world record (read it back as character.id); the player is 'player', an NPC its record id
  - `clips?: { idle?, walk?, run?, swim?, jump?, fall?, … } | null` Action name mapping { idle, walk, run, swim, jump, fall } (shorthand for animation)
  - `animation?: AnimatorOptions | null` Skeletal animation state machine config (states, blend trees, one-shot actions), see AnimatorOptions
  - `mover?: 'simple' | 'rapier' | 'manual' | …` Movement method: 'simple' built into the engine (default) / 'rapier' Rapier character controller (needs the rigid module) / 'manual' the game writes the position, move() only updates grounded / support / safeGround / fall
  - `faceMode?: FaceMode` Which way it turns each move: 'move' (default, toward its velocity) / 'camera' (along cameraRig.forward()) / 'target' (toward faceTarget) / 'manual' (only face() turns it)
  - `faceTarget?: PositionLike | null` What faceMode 'target' faces (lock-on)
- **FindSpawnOptions** Parameters of findSpawn(): minH/maxH height range (meters, default unlimited), maxSlope maximum slope (default 0.3), waterMargin minimum meters above the water (default 0.5)
  - `minH?: number`
  - `maxH?: number`
  - `maxSlope?: number`
  - `waterMargin?: number`

## engine.npcs (installed together with characters())
- `npcs.list() → NPC[]` — All NPCs (including far ones and ones in other levels)
- `npcs.add(opts: NPCOptions) → NPC` — Add an NPC, returns a handle
- `npcs.remove(npc: NPC | string) → boolean` — Delete an NPC (pass a handle, id or name): the data is deleted, and the model and dialogue interaction are torn down together. Returns false if not found
- `npcs.behavior(name: string, impl: { near?, far? })` — Register an NPC behavior: near(rec, dt, npc) once per fixed step when nearby, far(rec, dt) simulated from the data when far (dt is accumulated seconds); selected through behavior in the data
- `npcs.tiers(opts: { fullRadius, nearEvery } | null)` — Near tiers for large crowds, off by default (every near NPC walks every fixed step). With tiers, NPCs within fullRadius m of the focus walk every step; the rest of the near zone takes a turn once every nearEvery seconds with the accumulated dt (deterministic, save-safe). On screen such NPCs move in visible jumps, so only turn this on for crowds of hundreds. tiers(null) turns it off. Example: `engine.npcs.tiers({ fullRadius: 30, nearEvery: 4 / 60 })`
- `npcs.get(idOrName: string) → NPC | undefined` — Find by id or name (id first)
- `npcs.character(id: string) → Character | null` — The current character model of an NPC, null if none
- Properties:
  - `avoid: { on, radius, strength, set, push }` Nearby NPCs avoid each other (on by default): pushed apart to no less than the sum of their radii, the player counts as an obstacle (NPCs yield to the player), then constrained back to walkable places by engine.collision; deterministic and cheap, with identical results after loading. With nav({ crowd: true }) crowd takes over. Example: `engine.npcs.avoid.set({ radius: 0.6, strength: 2 });   // set(false) turns it off`
