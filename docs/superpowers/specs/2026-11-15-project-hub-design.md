# 引擎主页（项目列表 + 照片墙）设计

日期：2026-11-15　状态：待用户确认

## 为什么做

用户不看代码，靠看画面了解游戏做到哪了。现在要看一个游戏得开命令、开浏览器、走到那个位置。AI 改完游戏后用户也不知道画面变成什么样。
目标：打开一个网页，看到自己所有游戏；点进一个游戏，看到它各个固定位置的最新截图，游戏改了截图自己更新。

## 目标

1. 引擎有一个网页界面（"主页"），用一条命令打开：`npx threedog hub`（装了 @threedog/tools 的地方都能用）。以后引擎的各个网页界面都从这里进。
1b. 桌面图标（用户要求）：双击桌面上的 threedog 图标就打开主页网页。主页里有"在桌面放图标"按钮，命令行也可 `threedog hub --shortcut`。Windows 上做成 .lnk：直接用 node 运行这份工具里的主页脚本（不经 npx，启动快），带引擎图标，命令窗口最小化运行（关掉那个窗口 = 关主页；页面里也有"关闭主页"按钮）。主页已在跑时双击只打开网页。工具被移走或删掉后图标会失效，主页启动时若发现桌面图标指向的不是当前这份，就自动改指向当前这份。Mac/Linux 不做图标，只提示命令（不进验收）。
2. 主页列出所有项目，每个项目一张卡片：名字、文件夹位置、一张封面（第一个点位的最新截图）、最后更新时间。
3. 主页能新建项目：填名字、选位置、选起点模板（空白 / 开放世界 / 像素 / 只有场景，就是 `threedog init` 现有的选项），点"新建"。也能"添加已有文件夹"。
4. 点进项目 = 照片墙：这个项目点位清单里每个点位一张最新截图，下面写名字和拍摄时间。点一张放大，能看到这个点位以前的几张（按时间），用来看改动前后。
5. 截图自动更新：主页开着时，盯着各项目的文件；某项目文件有改动，等到 30 秒内没有新改动，就把这个项目的所有点位重拍一遍。页面不用刷新，新照片自己换上。另有"现在重拍"按钮。
6. 点位由 AI 定：每个项目一份点位清单，AI 做游戏时自己加、改。

## 不做

- 不做桌面软件（Electron 之类），只做本地网页。
- 不在主页里写代码、派活给 AI、改游戏内容（编辑器已有，从主页加个链接即可）。
- 不联网、不上传，只在本机。
- 不为手机做布局优化（手机不进验收）。
- 不做多人。

## 反目标（做出来也算失败的情况）

- 自动重拍把笔记本卡住：同一时间只拍一张，拍照排队；用户的游戏开发服务器或其他重活在跑时也只是排队，不并行开多个无头浏览器。
- 照片墙显示的是旧图却看不出来：每张都写拍摄时间；拍失败的显示失败原因（一句话），不悄悄留旧图。
- AI 写点位还要另学一套：点位直接复用已有的拍照选项。

## 做法（已选）

考虑过三种：
1. **本地网页 + 后台常驻命令**（选这个）：复用引擎现有的开发服务器、拍照工具、新建工具，新代码最少，跟着 @threedog/tools 一起发布。代价：要开着这个命令才会自动拍。
2. 桌面软件：双击即开，但多一整套打包和维护，照片墙核心功能一样，现在不值得。
3. 只生成静态照片墙网页：最简单，但做不到自动更新，不符合要求。

用户确认：网页就行，引擎界面也用网页。

## 已定的部分

### 点位清单

- 放在项目根目录 `shots.json`（提交进仓库，AI 可编辑）。
- 每条是一个点位，字段就是 `threedog shot` 已有的选项，不另造：
  ```json
  [
    { "name": "村口全景", "cam": [0, 12, 30, 0, 0, 0] },
    { "name": "主角特写", "view": "character", "play": true },
    { "name": "黄昏下雨", "view": "overview", "time": "18:30", "weather": "rain" },
    { "name": "商店内", "at": "shop", "play": true, "wait": 2 }
  ]
  ```
  可用字段：`name`（必填，照片墙上显示的名字，也是文件名依据）以及 `view` / `cam` / `pos` / `at` / `play` / `time` / `weather` / `wait` / `size`，含义与 shot 工具相同。
- 没有 `shots.json` 的项目：照片墙拍一张默认画面（等于不带参数的 shot），并提示"还没有点位清单"。
- 新建项目的模板里带一份只有一个点位的 `shots.json`。
- 引擎给 AI 的说明（`threedog how` 能查到的那套，以及模板里的 CLAUDE.md/AGENTS.md）补一句：做出新的地方或画面变化后，往 `shots.json` 加点位。

### 项目列表存在哪

- 本机用户目录下 `~/.threedog/projects.json`，只存文件夹路径列表。
- `threedog init` 成功后自动登记；主页"新建"和"添加已有文件夹"也写这里；文件夹不在了，卡片显示"找不到"并给"移除"按钮。

### 截图存在哪

- 每个项目自己的 `.threedog/wall/` 下（`.threedog/` 已不进仓库）。每个点位保留最近 10 张，按时间命名；再多删最旧的。

### 什么算"文件改动"

- 盯项目文件夹，忽略 `node_modules`、`.threedog`、`dist`、`.git`。
- 只有主页打开（命令在跑）时才盯。命令启动时，若某项目文件比它最新截图新，就排一次重拍。

### 施工方读稿后补定（协调者的决定）

- **打开游戏 / 编辑器 / 素材展示**：卡片和照片墙上有"打开"按钮，点了由主页为这个项目起开发服务器（复用 browser.mjs 的 devServer），再打开对应网址。同一时间只给一个项目起开发服务器，点另一个项目会先关掉前一个；关主页时一起关。
- **拍照代码**：把 shot.mjs 的核心拆成可复用的"一次构建、一个浏览器、连拍 N 个点位"函数，`threedog shot` 命令变成它的薄包装，命令的选项和输出保持不变。主页每轮重拍一个项目只构建一次。
- **入口页面**：默认 `/`；点位可加 `page` 字段（同 shot 的 page 参数）拍别的页面。
- **"添加已有文件夹"的校验**：package.json 依赖了 `threedog` 才接受，否则一句话说明为什么不收。
- **出错**：一个点位失败不影响其他点位，失败的那张显示一句原因；`shots.json` 写坏了（不是合法 JSON）在项目卡片上报错；不认识的字段报错并点名字段和点位（严格，方便 AI 改对）。
- **单实例**：固定默认端口；已有主页在跑时，再执行 `threedog hub` 只打开已有的那个，不起第二个。
- **测试不碰真实用户目录**：项目列表的位置可用环境变量 `THREEDOG_HOME` 改。
- **状态记录**：每个项目 `.threedog/wall/index.json` 记每个点位的照片列表、拍摄时间、失败原因。"最后更新时间" = 最新一张照片的拍摄时间。启动时按项目比较"最新文件改动时间"和"上次重拍时间"。改 `shots.json` 也算改动，整组重拍。

## 留给施工方决定

- 网页长什么样（简洁、能看清图即可；深浅色都能看）。
- 拍一个项目所有点位时，是每张调一次 shot，还是开一次浏览器连拍（后者更快，优先考虑，但要和现有拍照工具共用代码，不另写一套）。
- 自动重拍时游戏要先构建，构建失败怎么在卡片上显示。
- 端口、命令输出的具体文字（遵守"工具输出要短"）。
- 测试范围：只测新加部分，少跑真实渲染。
